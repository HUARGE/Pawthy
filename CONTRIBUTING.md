# Contributing to Pawthy

## Branching (Git-Flow)
- `main`: stable, release-ready code
- `develop`: integration branch
- `feature/<issue-no>-short-description`: one branch per task

## Commit messages
Format: `type: description (#issue)`
Types: feat, fix, docs, chore, refactor, test
Example: `docs: add project proposal draft (#4)`

## Pull requests
1. Branch off `develop`
2. Open a PR into `develop`
3. At least 1 approval is required
4. Resolve all review conversations before merging
